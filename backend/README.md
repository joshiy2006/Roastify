# Roastify API

FastAPI backend for the Spotify/Steam roaster.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

## Run

```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

Health check: `GET http://127.0.0.1:8000/health`

## Spotify OAuth local setup (read this if login gives a blank page or "not configured")

Spotify enforces (as of November 2025) that loopback redirect URIs use the IP literal
`127.0.0.1`, not the hostname `localhost` — and browsers treat those two hostnames as
different sites for cookies. That means for local dev, **everything has to agree on
`127.0.0.1`**:

1. In your [Spotify app dashboard](https://developer.spotify.com/dashboard), register the
   redirect URI as exactly `http://127.0.0.1:8000/auth/spotify/callback`.
2. `backend/.env`: `SPOTIFY_REDIRECT_URI=http://127.0.0.1:8000/auth/spotify/callback` and
   `FRONTEND_ORIGIN=http://127.0.0.1:5173` (both already the defaults).
3. `frontend/.env`: `VITE_API_BASE_URL=http://127.0.0.1:8000` (already the default).
4. **Open the frontend in your browser at `http://127.0.0.1:5173`, not `http://localhost:5173`.**
   If you load the app via `localhost`, the OAuth session cookie set during the callback
   won't be sent back on the roast fetch, and the flow will silently fail.

If you still get stuck: check the browser's dev tools Network tab for the `/roast/spotify`
request status, and the backend's terminal output for a logged exception.

## Endpoints

- `GET /roast/steam?handle=...` — roast for a Steam ID/vanity URL, built from a mock
  library (real Steam Web API integration is blocked on the account needing $5+ lifetime
  spend to issue a key) and generated by Groq
- `GET /roast/spotify` — roast for the connected Spotify account's real top artists/genres,
  generated by Groq; requires an active OAuth session (see above)
- `GET /auth/spotify/login` — redirects to Spotify's OAuth consent screen (needs
  `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET` set)
- `GET /auth/spotify/callback` — OAuth callback; sets the session cookies and redirects
  back to the frontend

Both roast endpoints fall back to a canned template roast if the Groq call fails for any
reason (bad key, rate limit, network error), so they always return a normal response.
